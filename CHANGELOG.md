- The Telegram client now intercepts deterministic trading commands before falling back to the Eliza LLM chat handler when `TG_TRADER=true`.
- Unknown slash commands now get a deterministic "Unknown command" reply with Help/Menu buttons instead of silently falling through to the Eliza LLM chat handler. Commands addressed to a different bot (`/command@OtherBot`) are ignored so Ribbot does not hijack group commands meant for other bots.
- Inline-button callbacks from older Ribbot messages (unknown actions or invalid token mints) now reply that the action is no longer available, with a Menu button, instead of silently doing nothing after the callback acknowledgment.
- The pasted-token trade panel and `/help` copy are now execution-mode aware: they describe whether confirmed tickets stay dry-run in Ribbot or route to FTX/FrogX live gates, instead of always claiming live execution is disabled.
- Dry-run confirmation and Send replies now attribute the block to Ribbot's own live gates and state that nothing was sent to FTX/FrogX, so users can tell a Ribbot-side gate from an FTX-side gate or execution failure.
- `/help`, `/wallet`, `/positions`, `/pnl`, wallet-missing prompts, and the empty `/orders`/`/withdrawals` states now include Menu/Wallet/Refresh navigation keyboards for a coherent button path through every command.
- Ignored `.state/` runtime files so Telegram offsets and trading state do not appear as untracked repo changes.
- `/wallet` and `/wallet <solana address>` now route through FTX/FrogX. Privy user/wallet creation belongs to FTX Worker secrets and Ribbot only stores non-secret wallet metadata.
- Sell commands now require an FTX/FrogX position snapshot and refuse to guess balances when positions are unavailable.
- `/limit`, `/stop`, `/trailing`, and `/dca` are deterministic trading commands instead of generic `/orders` placeholders. They now require FTX order storage for new staged tickets. The FTX cron scanner can evaluate stored orders when explicitly enabled, but Telegram commands themselves do not start swaps, signing, or broadcast.
- Withdrawals are FTX-executed only after an explicit Send callback and live gates. Ribbot does not build, sign, broadcast, or schedule transfer transactions.
- Copytrade, sniper, auto-buy, and auto-sell can execute only from the FTX monitor under explicit FTX live gates, source/trigger checks, account/config opt-in, RPC/risk checks, and Privy signer checks. Bundle-buy can execute only from an explicit user callback routed through FTX live gates. Ribbot never builds copied/sniper/auto/bundle swaps, signs, broadcasts, or schedules execution.
- Local trading state is now a non-secret cache for FTX account snapshots. When FTX account storage is available, preference changes sync from FTX instead of relying on Ribbot as the only preference store.
- Token cleanup is review/staged only. Ribbot does not mutate hidden-token state or sell tokens directly from the review card without the user pressing a specific Hide or Sell action.
